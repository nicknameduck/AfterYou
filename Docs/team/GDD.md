### 1.1 게임 정체성

- **장르 본질**: 물리 시뮬레이션이 아니라 **"과거의 나를 녹화·재생해 협력"** 하는 타임 클론 퍼즐. 물리(밟기·밀기·무게)는 협력을 성립시키는 보조 규칙일 뿐.
- **재미의 축**: 순서와 역할 배분의 사고 — "누구를 언제 움직여, 어떤 세팅을 남기고, 다음 클론이 그 위에 무엇을 쌓는가."
- **차별화 비중**: 메커니즘 70% + 가벼운 내러티브 래핑 30%.
- **최대 리스크 & 대응**: 이 장르의 고질병은 "해법을 알아도 실행이 빡세서 짜증"(레퍼런스 *Rewind* 혹평 사유). → **두뇌 퍼즐 우선, 실행은 넉넉한 판정**으로 정면 회피.

### 1.2 핵심 검증 질문 (프로토타입에서 검증할 단 하나)

> **"순서를 고민하며 클론을 배치해 퍼즐을 푸는 게 재밌는가?"**

Phase 2(§10) 도달 시 이 질문에 "예"가 나와야 개발 지속. 밋밋하면 코어 재고.

## 2. 레퍼런스

> 같은 장르(녹화/재생 클론 협력)의 Steam 출시작. 볼륨·완성도 기준점과 실패 회피 사례.

| 게임 | 참고 요소 | 교훈 |
|---|---|---|
| **RE-TAPED** | 녹화/재생 유령 클론, 29개 수제 레벨, 스테이지마다 새 메커니즘 도입 | 메커니즘 점진 도입 커리큘럼 |
| **Record Rewind Repeat** | 50개 수제 레벨, 시간 기록 복제 협력 | 볼륨 상한 참고 |
| **Rewind** | 클론 협력, 약 4시간 분량 | ⚠️ **조작 정밀도 스트레스로 혹평** → 우리는 "넉넉한 판정"으로 회피 |
| **Causal Loop** | 최대 3명의 과거 자신 녹화·재생 + 내러티브, 리뷰 91% 긍정 | 소수 클론 + 가벼운 서사의 성공 사례 |

> **핵심 교훈**: 이 장르 볼륨 기준점은 **29~50레벨 / 3~4시간**. 첫 작품은 하한선(**25~30레벨 / 2~3시간**) 목표. 실행 난이도를 낮추고 두뇌 퍼즐에 집중.

## 3. 핵심 컨셉

**장르**: 타임 클론 / 레코드-앤-리플레이 퍼즐 플랫포머 (횡스크롤)

**한 판의 흐름**:
1. 캐릭터 하나를 조작 → 그 동작(궤적)이 녹화됨
2. 리셋 → 다음 캐릭터를 조작 (이전 캐릭터들은 녹화된 궤적을 그대로 재생)
3. 여러 "과거의 나"가 협력해 스위치를 밟고, 발판이 되고, 길을 열어 → 출구 도달 = 클리어

### 3.1 확정된 코어 시스템

> **[결정됨 2026-07-07]** 아래 항목 확정.

| 항목 | 결정 |
|---|---|
| 녹화 방식 | **순차 녹화형** — 한 번에 한 캐릭터 조작, 나머지는 재생 |
| 캐릭터 순서 | **자유 선택** — 다음에 누구를 조작할지 플레이어가 고름 (순서 자체가 퍼즐) |
| 정체성 | **클론마다 고정** (실시간 전환 없음). 레벨별로 정체성 구성이 미리 정해짐 |
| 정체성 종류 | **코어 4종** (무거운 / 가벼운 / 운반 / 벽타기). 확장 4종은 백로그(§12) |
| 클론 개수 | **레벨별로 고정 지급** (전역 무제한·임의 생성 아님). 종류+개수를 레벨 설계자가 함께 정함. 가이드라인: 레벨당 2~4명(3명 표준, 5+ 비추천). 덜 쓰고 클리어 = 챌린지 보너스 |
| 물리 규칙 | 3개 (§6: 클론 밟고 올라서기 / 물체 밀기·쌓기 / 압력판 무게 판정) |
| 녹화 실수 시 | **현재 캐릭터만 재녹화** (+ 되감기 편의기능). 레벨 전체 리셋 안 함 |
| 난이도 성격 | **두뇌 퍼즐 우선, 실행은 넉넉한 판정** (정밀 조작 스트레스 최소화) |
| 차별화 비중 | 메커니즘 70% + 가벼운 내러티브 래핑 30% |

## 4. 코어 게임 루프

```
┌────────────────────────┐
│  1. 캐릭터(정체성) 선택 │  이번에 조작할 클론을 자유 선택 (순서가 곧 퍼즐)
└───────────┬────────────┘
            ↓
┌────────────────────────┐
│  2. 조작 + 녹화        │  이동/점프/상호작용. 궤적이 FixedUpdate마다 기록됨
│                        │  (이전에 확정한 클론들은 동시에 궤적 재생 중)
└───────────┬────────────┘
            ↓
┌────────────────────────┐
│  3. 녹화 종료 / 확정    │  현재 클론을 스택에 push. 그가 만든 환경 변화도 귀속·확정
└───────────┬────────────┘
            ↓  실수했다면 → 라운드 리셋(현재 클론만 pop) 후 2로  (§7)
┌────────────────────────┐
│  4. 클리어 판정        │  모든 역할이 맞물려 출구 도달? → YES: 클리어 / NO: 다음 클론
└───────────┬────────────┘
            ↓  클리어 시
┌────────────────────────┐
│  5. 동시 재생 리플레이  │  전 클론이 한꺼번에 재생되는 연출 (장르의 쾌감 포인트, §9)
└───────────┬────────────┘
            ↓  (다음 레벨로)
```

### 4.1 반복 동작

**별도 구현 불필요.** 녹화 방식상 플레이어가 반복 움직임을 녹화하면 재생 시 자동 반복됨. 녹화 시간 상한만 넉넉히 설정할 것.

## 5. 정체성 시스템

> **설계 원리**: 각 정체성은 "혼자 할 수 있는 것"과 "절대 못 하는 것"이 명확해야 한다. 못 하는 것이 있어야 다른 클론에게 의존하게 되고, 그 의존 사슬이 퍼즐이 된다. 각 종류는 **고유 동사(다른 종류가 못 하는 일)** 하나를 반드시 가진다.

### 5.1 코어 4종 (첫 출시)

| 정체성 | 고유 동사 | 할 수 있는 것 | 못 하는 것 |
|---|---|---|---|
| **무거운형** | *누른다* | 압력판 유지, 발판 역할, 무게 | 높이 못 감, 남의 등 못 밟음(너무 무거워 짓누름) |
| **가벼운형** | *높이 오른다* | 높은 점프, 클론 밟고 도약 | 압력판 무게 부족, 물체 못 옮김 |
| **운반형** | *옮긴다* | 물체 밀기·들기·전달, 스위치 조작 | 특출난 이동 능력 없음(연결고리 역할) |
| **벽타기형** | *붙는다* | 벽·천장 이동, 수직 공간 개척, 남의 발판 됨 | 물체 못 만짐 |

### 5.2 확장 4종 (백로그 — §12)

출시 후 업데이트 / 후반 챕터 후보. 각각 고유 동사 보유.

| 정체성 | 고유 동사 | 설명 |
|---|---|---|
| 긴/큰형 | *잇는다* | 간극을 몸으로 다리 |
| 던지기형 | *보낸다* | 물체 원거리 투척 |
| 부유형 | *떠서 횡이동한다* | 긴 간극 공중 횡단 |
| 소형 | *좁은 곳을 지난다* | 작은 틈 통과 (※ 고유성 약한 편, 마지막 후보) |

## 6. 물리 상호작용 규칙

MVP 물리 규칙은 **3개로 고정**. (물리 시뮬레이션 자체가 아니라, 클론 협력을 성립시키는 최소 규칙)

1. **클론 위에 올라서기** — 가벼운형이 무거운/운반형을 밟고 높은 곳 도달. 벽타기형도 발판이 됨.
2. **물체 밀기·쌓기** — 운반형 전용.
3. **압력판 무게 판정** — 무거운형 필요.

### 6.1 홀드 vs 토글 (리셋과 연동 — §7)

| 종류 | 동작 | 지속성 |
|---|---|---|
| **토글 스위치 / 열린 문 / 만들어진 다리** | 한 번 작동 = 영구적 변화 | 그것을 만든 클론이 확정돼 있는 한 유지 |
| **홀드 스위치 (압력판)** | 누군가 **계속 밟고 있어야** 작동 | 밟는 클론이 재생 중 발을 떼면 원상복구 → **클론을 소모하는 자원** |

## 7. 리셋 규칙 (2층위 + 스택형)

> **핵심 원칙**: 환경 변화는 그것을 일으킨 클론에 **귀속**된다. 클론이 확정되면 그 변화도 확정, 클론이 리셋되면 그 변화도 함께 리셋된다.

### 7.1 두 층위의 리셋

| 리셋 | 범위 |
|---|---|
| **전체 리셋** (스테이지 처음부터) | 지금까지 배치한 모든 클론 + 모든 환경 → 스테이지 초기 상태로 초기화 |
| **라운드 리셋** (현재 클론 재녹화) | 현재(가장 최근) 클론 + **그 클론이 일으킨 환경 변화만** 되돌림. 이전 클론들과 그들이 만든 세팅은 유지 |

### 7.2 스택형 되돌리기

- 클론은 쌓인 순서대로만 되돌릴 수 있음 (최근 → 과거 순)
- 중간 클론을 고치려면 그 위에 쌓인 클론부터 차례로 되돌려야 함
- 이유: 클론들이 서로의 세팅에 의존하며 쌓이므로, 중간 걸 함부로 바꾸면 그 위에 쌓은 게 무너짐

### 7.3 구현 관점

자연스럽게 **undo 스택** 구조가 됨.
- 클론 1개 = 스택의 한 층 = `{궤적 + 이 클론이 바꾼 환경 변경 리스트}`
- 라운드 리셋 = pop, 새 클론 확정 = push

## 8. 구현 기술 방향 (Unity)

### 8.1 입력 기록 = 위치(transform) 기록 방식 채택

- 매 `FixedUpdate`마다 캐릭터의 `{위치, 바라보는 방향, 상태}`를 리스트에 저장
- 재생 시 클론은 저장된 궤적을 그대로 따라감 → **100% 일치 재현** (물리 재시뮬레이션 방식의 desync 문제 회피)

### 8.2 재생 클론 = Kinematic Rigidbody2D

- 궤적대로 이동하되 외력엔 안 밀림
- 단, 현재 조작 캐릭터가 클론을 **밟거나 밀 때는 물리적으로 반응**해야 함 → **현재 캐릭터는 정상 물리(Dynamic)** 로 처리
- 압력판 판정은 클론의 현재 위치 + 정체성만 체크하면 됨 (단순)

## 9. 레벨 & 재미 설계

### 9.1 "아하 순간" 퍼즐 패턴

- 순서 자체가 퍼즐 (누구를 먼저 움직여야 하는가)
- 하나의 클론이 두 역할을 시간차로 수행 (먼저 발판, 나중에 이동)
- 겉보기엔 클론이 부족해 보이지만 재사용으로 해결
- 의존 사슬: 가벼운 애가 무거운 애의 길을 연다 (발판 배치 / 이동수단 개방 / 스위치 활성화)
- 미끼·희생 (클론이 함정을 대신 밟아 다음 클론의 길을 염)

### 9.2 시간축 타이밍 퍼즐 (심화 티어, 후반 챕터 전용)

- 앞 클론이 이동발판/엘리베이터/함정개폐를 특정 타이밍으로 조작 → 뒤 클론이 그 "창(window)"에 맞춰 통과
- **완화 필수**: 넉넉한 판정창, 발판 정지구간 길게, 되감기 허용
- 전체 레벨의 **20~30%로 제한, 챕터 3 이후 배치** (초반 진입장벽 방지)
- 장점: 공간 + 시간을 동시에 푸는 상급 재미

### 9.3 클리어 리플레이 연출

클리어 후 **전 클론 동시 재생** 리플레이 — 이 장르의 쾌감 포인트. (§4.1 루프 5단계)

## 10. 개발 로드맵

> **핵심 원칙**: Phase 2까지가 "이 게임 되냐 안 되냐"의 전부. 알바 병행이면 **2~3주 안에 Phase 2 도달 → 재미 검증**이 최우선. Phase 3부터는 "얼마나 잘 채우냐"의 문제라 시간 배분 유연.

### Phase 0 — 프로젝트 세팅
- [ ] Unity 2D 프로젝트 생성, 씬/폴더 구조
- [ ] 임시 에셋(무채색 도형): 무거운=큰 네모, 가벼운=작은 동그라미
- [ ] 기본 2D 캐릭터 이동 + 점프 (Rigidbody2D)

### Phase 1 — 코어 시스템 (재생-녹화의 심장) ⭐
- [ ] 위치 기록 시스템 (FixedUpdate마다 궤적 저장)
- [ ] 재생 시스템 (kinematic 클론이 궤적 따라감, 100% 일치)
- [ ] 순차 플로우 (조작 → 녹화 종료 → 리셋 → 다음 캐릭터 재생 → 반복)
- [ ] 캐릭터 순서 자유 선택 UI
- [ ] 현재 캐릭터만 재녹화 + 되감기
- [ ] 출구 도달 = 클리어 판정

### Phase 2 — 정체성 + 물리 (코어에 깊이 부여) ⭐ 검증 지점
- [ ] 정체성 2종 먼저 (무거운 / 가벼운)
- [ ] 물리 규칙 2개 (클론 밟고 올라서기 / 압력판 무게 판정)
- [ ] **검증용 레벨 3~5개 제작**
  - 레벨 1: 클론 1이 압력판 밟고 → 그 문으로 클론 2 통과 (기본 협력)
  - 레벨 2: 가벼운 클론이 무거운 클론 밟고 높은 출구 도달 (물리 규칙)
  - **레벨 3: 순서 틀리면 못 푸는 레벨 (순서=퍼즐 증명 — 핵심 테스트)**
  - 레벨 4~5: 조합 심화
- [ ] ⚠️ **판단 지점**: 여기서 "재밌다"가 확인돼야 진행. 밋밋하면 코어 재고. (§1.2 검증 질문)

### Phase 3 — 코어 완성 (검증 통과 후)
- [ ] 운반형 정체성 + 물체 밀기·들기 규칙 추가
- [ ] 벽타기형 정체성 + 벽·천장 이동 구현 (코어 4종 완성)
- [ ] 환경 기믹 6~8종 (홀드/토글 스위치, 시간제한 문, 이동 발판, 가시, 낙하 구멍)
- [ ] 클리어 후 "전 클론 동시 재생" 리플레이 연출
- [ ] 리셋 시스템: undo 스택 구조로 라운드/전체 리셋 구현

### Phase 4 — 콘텐츠 (볼륨 채우기)
- [ ] 레벨 커리큘럼 설계 (기믹을 하나씩 가르치는 난이도 곡선)
- [ ] 챕터 1~2: 순수 공간 퍼즐
- [ ] 챕터 3+: 시간축 타이밍 퍼즐 (완화장치 필수, 전체의 20~30%만)
- [ ] 목표 25~30레벨 / 2~3시간

### Phase 5 — 게임 완성도 (상업 출시 준비)
- [ ] 세계관/아트 톤 적용 (이때쯤 프로토타입 감으로 결정)
- [ ] 사운드, UI/메뉴, 스테이지 셀렉트, 세이브
- [ ] 별점 챌린지(최소 클론/이동) 등 리텐션 요소
- [ ] 스팀 페이지, 빌드, 테스트, 이름 최종 확인(상표/중복)

## 12. 백로그 (첫 출시 제외)

속편·업데이트용.

- **무한 루프 지정 기능** (클론 특정 구간 무한 반복) — UI·설계 복잡도 대비 효용 낮음
- **정체성 실시간 전환** — 퍼즐 제약 무너뜨림. 살린다면 "전환대 타일" 환경 기믹으로 후반/속편에
- **확장 정체성 4종** (§5.2: 긴/큰형·던지기형·부유형·소형) — 출시 후 업데이트 시 콘텐츠 마케팅 효과. 각자 고유 동사 확보 확인 후 도입
- **확장 환경 기믹** (중력 전환, 텔레포터, 컨베이어, 물/용암, 부술 수 있는 벽, 레이저)
- 타임어택 / 클론수 제한 모드
- 수집품 / 숨겨진 요소
