### 코드 설명

#### 컨테이너/자료구조 선택 이유
- 타임라인은 `List<ChainEvent>`(값 구조체) 3벌로 수명 분리: 기믹 로그(테이크 스코프) / 확정 착지(슬롯 꼬리표 — 되감기 삭제가 단일 역순 루프) / 임시 착지(테이크 스코프). 재생 대상은 복사본 List로 절연 — ResetUndoStack이 _confirmedSlots를 비운 뒤에도 재생 안전

#### 함수 설명
- ChainTimelineTracker.BuildTimeline: 리플레이 시작 직전 1회 호출, 고리 수 N 확정
- ReplayDirector.Begin: 보드를 시작 상태로 리셋 후 재생 개시. FixedUpdate가 코어와 동일 순서(박스→기믹→클론)로 구동
- EndReplay(완주/스킵 공통): undo 스택 리셋 + UI 숨김. StopImmediate(레벨 정리/ESC 경유)는 동일 후처리하되 곧 Teardown될 RoundManager는 안 건드림

#### 복잡한 코드 설명
- 타임라인 발화가 `==`가 아닌 `<=` 소급인 이유: 이벤트 스탬프는 발행자 각자의 FixedUpdate/Update에서 찍혀 중앙 틱 증가와 실행 순서 비보장(±1틱) — 등호면 고리가 조용히 유실
- "사전 스캔"을 기하 재계산이 아닌 플레이 중 이벤트 로깅으로 구현: 결정론 재생이 일치를 보장하므로 기록이 곧 예언. 판정 로직 이중 구현 회피
