### 코드 설명
#### 컨테이너/자료구조 선택 이유
- **포탈 허용 리스트 = IdentityData[] 에셋 참조**: 문자열/enum 비교 대신 SO 참조 동일성(`==`) — 새 정체성 추가 시 코드 무수정, 기존 데이터주도 패턴과 일관
- **지지체 질의 별도 버퍼**: 바깥 탑승자 루프가 쓰는 버퍼를 안쪽 질의가 재사용하면 순회 중 오염 — 재사용 List 2개 분리

#### 함수 설명
- `CrumblingPlatform.DriveGimmickTick`: 미붕괴 시 점유 질의 → 최초 점유 틱에 카운트다운 래치 → 매 틱 감소(점유 무관) → 0에서 붕괴. 한 번 트리거되면 진행이라 바운스 이중 엣지 무해
- `IdentityPortal.DriveGimmickTick`: 래치 중이면 이탈 감시만(마스크 1 — 513이면 클론이 영구 래치 유발), 비래치면 점유→정체성 검사→SetPosition+상대측 래치
- `MovingPlatform.CarryRiders`(수정): 3단 배제 후 delta 위치 가산 — 속도 기반 금지 규약 유지

#### 복잡한 코드 설명
- **래치를 출발측이 거는 이유**: 도착측 자체 감지에 맡기면 DriveGimmicks 배열 순서에 따라 같은 틱에 도착측이 즉시 되돌려보내는 핑퐁 발생
- **배제 조건이 "중심 포함 지지체"로 좁은 이유**: "다른 콜라이더가 잡히면 제외"로 넓게 잡으면 발판 위 라이브에 밀착한 클론 몸통이 잡혀 정당한 탑승자를 오배제(캐리 끊김 낙하)
- **텔레포트 속도 보존은 의도**: 결정성 무해, 낙하 관성째 도착 — 고속 낙하 진입 배치만 유의
