### 코드 설명
#### 컨테이너/자료구조 선택 이유
- **인터페이스 2분할(IActivatable/ITickGimmick)**: "배선 수신"과 "틱 세계 편입"은 별개 관심사 — 문은 수신만, 스위치는 구동만, 발판은 둘 다 필요해서 하나로 합치면 빈 구현이 강제된다
- **`MonoBehaviour[] _targets` + Awake 캐스트**: Unity가 인터페이스 직렬화를 지원하지 않아 MonoBehaviour로 받고 IActivatable 캐스트 검증(실패 시 LogError)
- **`ITickGimmick[]` 배열 주입**: 기존 `_boxes` 패턴과 동일 — 레벨 로드 시 한 번 수집, 매 틱 순회는 할당 0

#### 함수 설명
- `RoundManager.DriveGimmicks(tick)`: FixedUpdate에서 DriveBoxes 직후·클론 재생 이전 호출. 클론과 동일 _tick 공유(뒤로 옮기면 1틱 어긋남)
- `RoundManager.OnLiveDied()`: KillZone이 호출. Recording 가드 후 `_isDeathPending=true`만 세움 — 처리는 FixedUpdate가 순회 완료 후 단일 지점에서 RestartTake + return
- `ToggleSwitch.DriveGimmickTick()`: 기하 판정(발바닥≥윗면)으로 점유 엣지 검출 → 토글 → 전 대상 SetActivated. "ON인데 전 대상 비활성"이면 자기 동기화 OFF
- `MovingPlatform.DriveGimmickTick()`: 위상+1 시점 위치를 MovePosition 목표로(클론 frames[t+1] 규약과 동일 근거), 이동 delta를 발판 위 라이브에 위치 가산(속도 기반은 PlayerController 하드셋에 소멸)

#### 복잡한 코드 설명
- **기믹 상태를 기록/재생하지 않는 이유**: 상태는 매 테이크 리셋 + 시간은 틱 환산 + 검출은 라이브·클론 겸용(513)이면, 클론 재생이 과거 스위치 조작을 재수행해 활성화 이력이 자동 재현된다 — 별도 기록이 불필요
- **사망 플래그 지연**: 순회 도중 RestartTake를 즉시 호출하면 리셋 이후 배열 뒤쪽 기믹만 한 번 더 구동돼 킬존 위치에 따라 1틱 desync(1회차 실측). 플래그 지연으로 desync 0 실측 확정
- **기믹 리셋 3경로**: RestartTake는 EnterSelecting을 우회하므로(주석 명시) 별도 리셋 필수 — Critic이 사전 적발한 항목
