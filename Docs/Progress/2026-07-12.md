### 코드 설명

#### 컨테이너/자료구조 선택 이유
- `RecordedFrame` = **struct**: 틱당 1개(15초×3클론 ≈ 2,250개) 누적 → 힙 할당·GC 압력 회피
- `List<RecordedFrame>` + `Add()`만 사용: `List`는 Count 초과 인덱스 **대입 불가**(`ArgumentOutOfRangeException`). 읽기는 `Mathf.Clamp`로 마지막 프레임 홀드 → 길이가 다른 클론들이 하나의 중앙 틱을 공유해도 안전
- 확정 스택 = `List<int>` 말단 push/pop: 되감기가 최근→과거 순서만 허용되므로 스택 시맨틱으로 충분

#### 복잡한 코드 설명 (핵심)
- **틱 오프셋 규약** (`ClonePlayback.cs:48-53`): FixedUpdate는 물리 시뮬 **이전**에 실행 → 현재 위치 = 틱 t의 *시작* 위치. `MovePosition`은 이번 스텝 동안 목표까지 이동 → 스텝 끝(= 틱 t+1 시작)에 도달. 따라서 틱 t에서 **`frames[tick+1]`**을 목표로 해야 라이브 궤적과 시점이 일치한다. `tick`을 그대로 쓰면 1틱 밀려 압력판/발판 타이밍 버그의 원인이 됨
- **공유 InputActionAsset 함정**: 캐릭터 3명이 같은 에셋을 참조하면 `OnEnable/OnDisable`에 레퍼런스 카운팅이 없어 전환 순서에 따라 액션이 최종 Disable → **2라운드부터 조작 불능**. `Instantiate(_inputActions)`로 인스턴스별 사본 확보 (Unity PlayerInput 공식 패턴)
- **접지 레이어 전환**: 접지 마스크가 Ground(8) 단독이라 클론(layer 0)은 접지로 인식 안 됨 → 클론 위에서 점프 불가. `CharacterActor`가 Clone→8, Live/Idle→0으로 전환. ⚠ 라이브를 8로 두면 GroundCheck가 자기 콜라이더를 잡아 무한 점프
- **bodyType 전환 순서**: Kinematic도 `linearVelocity`가 남으면 관성 이동해 MovePosition과 충돌 → 속도 0 → bodyType → layer → 컴포넌트 → SetActive 순서 엄수
- **좌표 소스**: 프리팹이 Interpolate라 `transform.position`은 보간값 → 기록/재생 모두 `Rigidbody2D.position` 기준

#### 함수 설명

### 정체성 수치 (수학적으로 코어 게이트 보장)

|---|---|---|---|---|---|

- `h = jumpForce² / 58.86` (mass 1, gravityScale 3)
- ⚠ **Light JumpForce 상한 14.96** — 초과 시 혼자 플랫폼에 올라가 코어 게이트 붕괴
- Weight 10/1 + required 10 → 가벼운형 3기 합 3 < 10 → **수학적으로 개방 불가**

### 코드 설명

#### 컨테이너/자료구조 선택 이유
- **정체성 = ScriptableObject**: 새 정체성(Phase 3 운반형/벽타기형)이 **코드 변경 없이 에셋 추가만으로** 확장됨
- **압력판 검출 = `ContactFilter2D` + 재사용 `List<Collider2D>`**: FixedUpdate마다 질의하므로 `OverlapBoxAll`(배열 반환)은 프레임당 GC 할당을 유발

#### 복잡한 코드 설명 (함정 4개)
- **무게 ≠ mass**: `AddForce(Impulse)`라 Δv = jumpForce/mass. Weight를 `Rigidbody2D.mass`에 대입하면 **도달고가 1/4로 붕괴**. → Weight는 압력판 판정 전용 순수 데이터, "높이 못 감"은 `_jumpForce`로만 표현
- **정체성 적용은 반드시 Awake**: `RoundManager.Start` → `SetMode(Idle)` → `SetActive(false)`. 실행 순서 미보장이라 Start에 두면 **영영 호출되지 않음**
- **ApplyIdentity는 필드 대입만**: Awake 간 순서 미보장 → 캐시된 참조(`_rigidbody`/`_moveAction`)를 건드리면 NRE. 대입한 3개 값은 매 프레임 읽히므로 늦은 주입 문제 없음
- **압력판은 기하 판정만**: 클론은 MovePosition이라 **`linearVelocity`가 항상 0** → 속도 기반 착지 판정은 무조건 실패. `bounds.min.y >= plateTop - tolerance`로 판정. 마스크 513(Default|Clone)으로 라이브·클론 **둘 다** 검출 + `GetComponentInParent<CharacterActor>()` 2차 필터(QueriesHitTriggers=1이라 Exit 트리거가 섞임)
