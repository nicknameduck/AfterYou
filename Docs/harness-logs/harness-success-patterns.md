## #1 — Phase 1 녹화·재생 코어 (2026-07-12) · `코어시스템` · 91점

### 핵심 접근

- **중앙 틱 단일 소유권**: 재생/기록 컴포넌트에서 `Update`/`FixedUpdate`를 전부 제거하고, 매니저의 `FixedUpdate` 하나가 틱을 소유한다. 매니저가 `재생 → 기록 → 틱 증가` 순서로 각 컴포넌트의 공개 메서드를 직접 호출한다. 컴포넌트별 자체 인덱스를 두면 스크립트 실행 순서/활성화 타이밍에 따라 서로 1틱씩 어긋난다.
- **틱 오프셋 규약을 코드 주석으로 못박기**: `FixedUpdate`는 물리 시뮬 이전에 실행되므로 "지금 위치 = 틱 t의 시작 위치"다. `MovePosition`은 이번 스텝 동안 이동하므로 **틱 t에서는 frames[t+1]을 목표로** 삼아야 원본 궤적과 시점이 일치한다. off-by-one은 컴파일도 통과하고 눈에도 잘 안 띄므로, 규약과 근거를 주석으로 남기고 `Debug.Assert(tick == FrameCount)`로 런타임 자체 검증을 건다.
- **모드 전환을 단일 메서드에 캡슐화 + 순서 고정**: `bodyType` / `layer` / 컴포넌트 on-off / `SetActive`를 한 곳(`SetMode`)에서만 만진다. 순서가 곧 안전장치다 — ①활성화 → ②속도 0 → ③bodyType → ④layer → ⑤컴포넌트 → ⑥비활성화. 비활성 오브젝트의 Rigidbody2D는 시뮬레이션에서 빠져 물리 조작이 먹지 않고, bodyType 전환 전에 속도를 0으로 만들지 않으면 잔류 관성이 `MovePosition`과 싸워 지터를 만든다.
- **레이어 전환으로 "밟을 수 있는 오브젝트" 만들기 (+ 역함정 회피)**: 재생 클론을 지면 레이어로 올려야 라이브의 접지 체크에 걸린다. 단, **라이브는 반드시 원래 레이어로 되돌린다** — `Physics2D.queriesStartInColliders`가 켜져 있으면 접지 체크 박스가 자기 콜라이더를 잡아 공중 무한 점프가 된다. 두 방향 모두 실측으로 확인할 것.
- **씬에 여러 인스턴스가 있으면 InputActionAsset을 `Instantiate`로 복제**: 액션 에셋을 공유하면 인스턴스들이 같은 `InputAction` 객체를 참조하고, `OnEnable`/`OnDisable`에 레퍼런스 카운팅이 없어 호출 순서에 따라 액션이 최종 Disable된다 → 2라운드부터 조작 불능. `Awake`에서 `FindActionMap` **이전에** 복제한다.
- **런타임 파생 값은 기록하지 말고 계산해 넣기**: 스프라이트 방향처럼 컨트롤러가 만들지 않는 상태는 기록 시점에 `linearVelocity` 부호로 파생시켜 프레임에 담는다. 죽은 필드를 만들지 않는다.
- **시간 상한은 초 단위 → 틱 수로 환산**: `Mathf.CeilToInt(초 / Time.fixedDeltaTime)`. 프레임 수를 하드코딩하면 Fixed Timestep 변경 시 조용히 깨진다.
- **좌표 기록은 항상 `Rigidbody2D.position`**: Interpolate가 켜져 있으면 `transform.position`은 렌더용 보간값이라 물리 권위 값이 아니다. 순간이동 시에는 `rb.position`과 `transform.position`을 **함께** 세팅한다.
- **소유권 판정은 태그/레이어가 아니라 참조 동일성으로**: 같은 프리팹에서 나온 오브젝트들(라이브/클론)은 태그·레이어로 구분할 수 없다. 매니저가 노출하는 "현재 주체" 프로퍼티와 `!=` 참조 비교로 거른다.

### 평가 시 통했던 검증 기법

- **플레이 모드 + `execute_code` 리플렉션 실측**: 정적 코드 읽기만으로는 "2라운드부터 조작 불능" 같은 상태 버그를 증명할 수 없다. 플레이 모드에 진입해 매니저의 public 메서드를 리플렉션으로 호출하고 private 필드(`_tick`, `_isGrounded`, 액션 인스턴스 ID)를 직접 읽어 라운드 전이를 강제 재현했다. (에디터가 포커스를 잃으면 프레임이 멈추므로 `Application.runInBackground = true`를 먼저 세팅할 것)
- **점프 도달고를 수치로 계산해 레벨 설계 검증**: `최대 상승 = v₀²/(2·g)`, `v₀ = jumpForce/mass`, `g = 9.81 × gravityScale`. 이 값으로 "지면에서는 목표 발판에 못 닿고, 클론 위에서는 닿는다"를 산술로 확인하면 코어 루프가 실제로 강제되는지 플레이 없이 판정할 수 있다.

### 재사용 조건

레코드-앤-리플레이 / 고스트 / 리플레이 등 **결정론적 물리 재생이 필요한 시스템** 전반에 적용된다. 특히 "동일 프리팹의 인스턴스가 라이브/재생 두 역할을 오가는" 구조(모드 전환·레이어 전환·입력 에셋 복제·참조 동일성 판정)라면 위 5개 항목이 그대로 체크리스트가 된다.
