## #1 — Phase 1 녹화·재생 코어 (2026-07-12) · `코어시스템` · 91점

### 핵심 접근

- **중앙 틱 단일 소유권**: 재생/기록 컴포넌트에서 `Update`/`FixedUpdate`를 전부 제거하고, 매니저의 `FixedUpdate` 하나가 틱을 소유한다. 매니저가 `재생 → 기록 → 틱 증가` 순서로 각 컴포넌트의 공개 메서드를 직접 호출한다. 컴포넌트별 자체 인덱스를 두면 스크립트 실행 순서/활성화 타이밍에 따라 서로 1틱씩 어긋난다.
- **틱 오프셋 규약을 코드 주석으로 못박기**: `FixedUpdate`는 물리 시뮬 이전에 실행되므로 "지금 위치 = 틱 t의 시작 위치"다. `MovePosition`은 이번 스텝 동안 이동하므로 **틱 t에서는 frames[t+1]을 목표로** 삼아야 원본 궤적과 시점이 일치한다. off-by-one은 컴파일도 통과하고 눈에도 잘 안 띄므로, 규약과 근거를 주석으로 남기고 `Debug.Assert(tick == FrameCount)`로 런타임 자체 검증을 건다.
- **모드 전환을 단일 메서드에 캡슐화 + 순서 고정**: `bodyType` / `layer` / 컴포넌트 on-off / `SetActive`를 한 곳(`SetMode`)에서만 만진다. 순서가 곧 안전장치다 — ①활성화 → ②속도 0 → ③bodyType → ④layer → ⑤컴포넌트 → ⑥비활성화. 비활성 오브젝트의 Rigidbody2D는 시뮬레이션에서 빠져 물리 조작이 먹지 않고, bodyType 전환 전에 속도를 0으로 만들지 않으면 잔류 관성이 `MovePosition`과 싸워 지터를 만든다.
- **레이어 전환으로 "밟을 수 있는 오브젝트" 만들기 (+ 역함정 회피)**: 재생 클론을 지면 레이어로 올려야 라이브의 접지 체크에 걸린다. 단, **라이브는 반드시 원래 레이어로 되돌린다** — `Physics2D.queriesStartInColliders`가 켜져 있으면 접지 체크 박스가 자기 콜라이더를 잡아 공중 무한 점프가 된다. 두 방향 모두 실측으로 확인할 것.
- **씬에 여러 인스턴스가 있으면 InputActionAsset을 `Instantiate`로 복제**: 액션 에셋을 공유하면 인스턴스들이 같은 `InputAction` 객체를 참조하고, `OnEnable`/`OnDisable`에 레퍼런스 카운팅이 없어 호출 순서에 따라 액션이 최종 Disable된다 → 2라운드부터 조작 불능. `Awake`에서 `FindActionMap` **이전에** 복제한다.
- **런타임 파생 값은 기록하지 말고 계산해 넣기**: 스프라이트 방향처럼 컨트롤러가 만들지 않는 상태는 기록 시점에 `linearVelocity` 부호로 파생시켜 프레임에 담는다. 죽은 필드를 만들지 않는다.
- **시간 상한은 초 단위 → 틱 수로 환산**: `Mathf.CeilToInt(초 / Time.fixedDeltaTime)`. 프레임 수를 하드코딩하면 Fixed Timestep 변경 시 조용히 깨진다.
- **좌표 기록은 항상 `Rigidbody2D.position`**: Interpolate가 켜져 있으면 `transform.position`은 렌더용 보간값이라 물리 권위 값이 아니다. 순간이동 시에는 `rb.position`과 `transform.position`을 **함께** 세팅한다.
- **소유권 판정은 태그/레이어가 아니라 참조 동일성으로**: 같은 프리팹에서 나온 오브젝트들(라이브/클론)은 태그·레이어로 구분할 수 없다. 매니저가 노출하는 "현재 주체" 프로퍼티와 `!=` 참조 비교로 거른다.

### 평가 시 통했던 검증 기법

- **플레이 모드 + `execute_code` 리플렉션 실측**: 정적 코드 읽기만으로는 "2라운드부터 조작 불능" 같은 상태 버그를 증명할 수 없다. 플레이 모드에 진입해 매니저의 public 메서드를 리플렉션으로 호출하고 private 필드(`_tick`, `_isGrounded`, 액션 인스턴스 ID)를 직접 읽어 라운드 전이를 강제 재현했다. (에디터가 포커스를 잃으면 프레임이 멈추므로 `Application.runInBackground = true`를 먼저 세팅할 것)
- **점프 도달고를 수치로 계산해 레벨 설계 검증**: `최대 상승 = v₀²/(2·g)`, `v₀ = jumpForce/mass`, `g = 9.81 × gravityScale`. 이 값으로 "지면에서는 목표 발판에 못 닿고, 클론 위에서는 닿는다"를 산술로 확인하면 코어 루프가 실제로 강제되는지 플레이 없이 판정할 수 있다.

### 재사용 조건

레코드-앤-리플레이 / 고스트 / 리플레이 등 **결정론적 물리 재생이 필요한 시스템** 전반에 적용된다. 특히 "동일 프리팹의 인스턴스가 라이브/재생 두 역할을 오가는" 구조(모드 전환·레이어 전환·입력 에셋 복제·참조 동일성 판정)라면 위 5개 항목이 그대로 체크리스트가 된다.

### 반복 성공 — Phase 3-1 운반형/박스 밀기 (2026-07-18, 99점)

> 캐릭터에만 있던 record-replay 코어를 **두 번째 오브젝트 클래스(박스)로 확장**. 위 코어 규약이 새 오브젝트 타입에 그대로 이식됨을 검증.

- **record-replay 대상을 늘릴 때 "중앙 틱에 훅만 추가"하고 코어 루프는 감싼다**: 박스도 자체 Update/FixedUpdate 없이 매니저의 `DriveBoxes(_tick)`가 틱 증가 **이전**에 호출해 클론과 동일 _tick을 공유. 캡처/재생 메서드(`CaptureBoxTick`/`ApplyBoxTick`)는 클론과 **동일한 `tick+1` 클램프**를 그대로 복제한다 — 두 재생 주체의 시점 규약이 어긋나면 클론과 박스가 1틱씩 밀려 "미는 손과 박스"가 분리돼 보인다. git diff로 중앙 틱 4단계·충돌 해소 본문 0-diff를 라인 단위로 증명.
- **"조작 권한"을 정체성 데이터 플래그로, 물리 모드로 강제**: `CanManipulateObjects` bool 하나가 라운드 시작 시 박스를 Dynamic(Record)로 열지/Frozen(Kinematic)로 둘지 결정한다. 비운반형은 Frozen=Kinematic이라 Dynamic 라이브가 물리적으로 밀 수 없음 → **순서 강제가 분기 없이 물리 규칙으로 성립**. "명시적 판정 차단"을 별도 if로 짜지 않고 bodyType으로 얻는다.
- **소유권 승격은 "실제로 움직였을 때만"**: 확정 시 `HasDisplacement(ε)`로 첫 프레임↔현재 위치 차를 재, ε 초과 이동한 박스만 슬롯 소유로 커밋(그 외 기록 폐기). 미소유 박스는 매 라운드 base로 리셋되고, 소유 박스는 누가 라이브든 항상 Replay. 되감기 시 `OwnerSlot==slot`인 박스만 소유 해제.
- **"밀기 감각"은 mass, "판 판정"은 Weight — #2의 분리 원칙을 박스에도**: 박스 `Rigidbody2D.mass=1` 고정(밀기 감각), 압력판은 박스의 `Weight`(순수 데이터, 여기선 10)를 합산. mass에 무게를 넣으면 미는 힘 대비 가속이 붕괴한다.

**검증 기법 추가**: 리플렉션으로 박스를 판 위로 순간이동(`rb.position` 세팅 + `Physics2D.SyncTransforms()`) 후 `MeasureWeightOnPlate()`를 직접 호출해 Weight 합산(=10)을 격리 실측. 문 개방은 `Door.SetOpen(true/false)` → `collider.enabled` 토글로 인과 확인. 무회귀는 박스 0개 레벨의 `_boxes.Length=0`(클린 프레임)과 Select/Rewind 무크래시로 증명.

## #2 — Phase 2a 정체성 + 압력판 (2026-07-17) · `데이터주도설계` · 97점

> #1의 "레이어 전환" / "점프 도달고 수치 검증" 기법을 재사용하되, **캐릭터 능력을 데이터로 분리**하는 새 축을 추가했다.

### 핵심 접근

- **"게임 규칙상의 수치"와 "물리 엔진 수치"를 절대 같은 필드에 담지 않는다**: 가장 큰 함정이었다. 정체성의 `Weight`(무게)를 `Rigidbody2D.mass`에 대입하고 싶은 유혹이 강하지만, `AddForce(Impulse)` 기반 점프는 `Δv = jumpForce / mass`라서 mass를 올리는 순간 도달고가 조용히 붕괴한다. **`Weight`는 압력판 판정 전용 순수 데이터**로 두고, "높이 못 간다"는 특성은 **오직 `jumpForce`로만** 표현한다. 이름이 물리 개념과 겹치는 데이터 필드에는 "이건 mass가 아니다"를 주석으로 못박는다.
- **"능력"을 LayerMask로 표현하면 분기가 사라진다**: "누가 남의 등을 밟을 수 있는가"를 `if (identity == Heavy)` 분기로 짜지 않는다. 접지 마스크에 대상 레이어를 **포함시키느냐 마느냐**로 표현하면(가벼운형 = Ground|Clone / 무거운형 = Ground) 컨트롤러 코드는 한 줄도 분기 없이 그대로 동작하고, 새 정체성은 에셋의 마스크만 바꾸면 된다. 부수 효과로 "물리적으로는 올라서지되 점프만 불가"라는 미묘한 사양이 **공짜로** 얻어진다(충돌은 물리 레이어, 점프는 질의 마스크라 서로 독립).
- **ScriptableObject 주입은 `Awake`에서, 그리고 "필드 대입만"**: 두 제약이 쌍으로 온다. ①매니저가 `Start`에서 캐릭터를 `SetActive(false)` 한다면 캐릭터의 `Start`는 **영영 실행되지 않는다**(실행 순서 미보장) → 주입은 반드시 `Awake`. ②그런데 `Awake`끼리도 순서가 미보장이라, 주입 메서드가 상대의 캐시된 참조(`_rigidbody`, InputAction 등)를 건드리면 NRE가 난다 → 주입 메서드는 **필드 대입만** 한다. 대입된 값은 어차피 매 프레임 다시 읽히고 모든 `Awake`는 첫 `Update`보다 먼저 끝나므로 늦은 주입 문제는 없다.
- **Kinematic 바디가 섞인 검출은 반드시 기하 판정으로**: `MovePosition`으로 움직이는 오브젝트는 `linearVelocity`가 **항상 0**이다. 속도 기반·착지 이벤트 기반 판정은 클론에서 100% 실패한다. "발바닥(`bounds.min.y`)이 판 윗면 높이에 있는가"라는 순수 기하 조건만이 Dynamic과 Kinematic **양쪽에 동일하게** 성립한다.
- **물리 질의 필터는 3중으로 쌓는다**: ①`ContactFilter2D` 레이어 마스크(라이브 Default + 클론 Clone을 **둘 다** 포함해야 "클론이 밟아도 눌린다"가 성립) → ②`useTriggers = false` (`QueriesHitTriggers`가 켜져 있으면 Exit 같은 트리거가 섞여 들어온다) → ③`GetComponentInParent<T>()` (콜라이더가 자식에 붙어 있을 수 있다). 매 틱 질의이므로 `OverlapBoxAll`(배열 반환) 대신 **`ContactFilter2D` + 재사용 `List`** 오버로드로 할당 0을 유지한다.
- **상태 통지는 "바뀐 순간"에만**: 홀드 스위치는 매 틱 상태를 재계산하지만, 통지는 `if (next == current) return;`으로 엣지에서만 보낸다. 매 틱 세터를 때리면 콜라이더/색 재설정이 무의미하게 반복된다.
- **매니저 배열 순회 대신 물리 질의로 "월드에 실재하는 것"만 묻는다**: 대기 캐릭터가 `SetActive(false)`인 설계에서 매니저의 캐릭터 배열을 순회하면 **씬에 없는 캐릭터까지 세어** 규약이 깨진다.

### 평가 시 통했던 검증 기법

- **`Physics2D.simulationMode = Script` + `Physics2D.Simulate(dt)` 수동 스테핑으로 점프 정점 실측**: #1은 도달고를 공식으로만 검산했지만, MCP 호출 사이에는 수십 프레임이 흘러 정점을 놓친다. 시뮬레이션 모드를 Script로 바꾸고 한 스텝씩 돌리며 `bounds.min.y` 최댓값을 추적하면 **정점을 결정론적으로 포착**할 수 있다(`try/finally`로 원복 필수). 공식 예측 0.83/1.83 대비 실측 0.71/1.70 — 이산 스테핑 손실만큼 낮게 나오므로, **공식만 믿고 마진을 0.1 이하로 잡으면 실제로는 깨진다.**
- **"실패해야 할 케이스가 올바른 이유로 실패하는지" 확인**: "가벼운형만으로는 문이 안 열린다"는 조건은 **검출 자체가 실패해도 똑같이 통과**한다. 그래서 내부 계측 메서드를 리플렉션으로 직접 호출해 `MeasureWeightOnPlate() = 2`를 확인했다 — 라이브(layer 0)와 클론(layer 9)이 **둘 다 검출됐고** 무게 합이 임계값에 미달해서 닫힌 것임을 증명. 음성 결과는 반드시 "검출은 됐다"를 함께 보여야 한다.
- **`Awake` vs `Start` 배치는 "비활성 상태에서 값이 들어있는가"로 증명**: 매니저가 캐릭터를 꺼놓은 시점에 리플렉션으로 주입값을 읽어 `jumpForce=10/14`가 이미 반영돼 있음을 확인했다. `Start`였다면 불가능한 상태이므로, 이 한 번의 관측이 곧 배치 검증이 된다.
- **`.mass =` 대입 전역 grep + 런타임 `rb.mass` 실측 이중 확인**: 정적 검색은 "지금 없다", 런타임 실측은 "어떤 경로로도 안 새어 들어왔다"를 각각 증명한다. 둘 다 해야 한다.

### 재사용 조건

캐릭터/유닛의 **능력 차등을 데이터로 분리**하는 모든 작업(직업·클래스·아이템·업그레이드)에 적용된다. 특히 ①규칙 수치가 물리 수치와 이름이 겹칠 때, ②능력 차이를 분기 대신 마스크/플래그로 표현할 수 있을 때, ③Kinematic·Dynamic이 한 검출 로직에 섞일 때 위 항목들이 그대로 체크리스트가 된다.

## #3 — Phase 2b 레벨=프리팹 교체 + 런타임 주입 (2026-07-18) · `시스템조립` · 99점

> 씬에 하드코딩돼 있던 매니저를 **데이터/씬 참조에서 떼어내 런타임 주입형 생명주기로 리팩터**하는 축. 기존 보호 코드(코어 루프)를 한 줄도 건드리지 않고 감싸는 것이 핵심.

### 핵심 접근

- **씬 직렬화 참조를 런타임 주입으로 바꿀 때 `[SerializeField]`만 떼면 된다**: 프리팹은 씬 오브젝트(씬의 RoundManager 등)를 직렬화 참조할 수 없다. 매니저의 `_characters`/`_spawnPoint`에서 `[SerializeField]`를 제거해 순수 private으로 만들고, 로더가 `Initialize(...)`로 주입한다. Unity는 씬에 남은 옛 직렬화 값을 **조용히 버리므로** 컴파일 에러도 경고도 없다(콘솔 실측으로 확인). 프리팹→씬 참조가 필요한 지점마다 `Bind*(sceneRef)` 세터를 두는 것이 정석(`LevelExit.BindRoundManager`, `CharacterActor.InjectIdentity`).
- **매니저 생명주기를 `Awake`/`Start`에서 `Initialize`/`Teardown` 공개 메서드로 승격**: 매니저가 스스로 시작하지 않고 로더가 명시적으로 시작/정지시킨다. `Initialize` 순서는 **주입 → 이전 잔재(컬렉션·오버랩) 전부 Clear → 틱/인덱스 리셋 → 부모/스폰 캡처 → `_initialized=true` → 상태 진입**. 잔재를 남기면 다음 레벨의 되돌리기가 **파괴된 Transform으로 SetParent**를 시도한다.
- **전환 안전은 단일 `_initialized` bool 가드로**: 레벨 언로드~로드 사이 한 프레임이라도 매니저의 입력/틱/재생이 돌면 null 참조로 터진다. 모든 외부 진입점(Update/FixedUpdate/Select/Confirm/Restart/Rewind/코루틴)에 `if(!_initialized) return`을 건다. **단, `_state`만 만지고 자체 가드가 있는 메서드엔 넣지 않는다** — 불필요한 가드는 절제한다(과방어 감점 회피).
- **Teardown의 리셋 순서가 곧 NRE 방어**: "현재 주체" 프로퍼티(`LiveCharacter => _liveIndex>=0 && _characters[_liveIndex]`)가 있으면, `_liveIndex=-1`을 `_characters=null`보다 **반드시 먼저** 한다. 인덱스를 먼저 무효화하면 단락 평가로 `_characters`에 접근하지 않는다.
- **비활성 부모 트릭으로 "주입 완료 후 Awake" 보장**: 캐릭터를 생성하며 정체성을 주입해야 하는데 `Awake`가 그 값을 읽는다. 부모를 `SetActive(false)`한 채 Instantiate·주입을 끝내고 **한 번에 `SetActive(true)`** 하면 전원의 `Awake`가 주입 완료 상태에서 실행된다. 매니저 `Initialize`는 반드시 `SetActive(true)` **후**에 호출(그래야 스폰 오버라이드가 Awake의 위치 캡처를 덮어쓴다).
- **파괴는 부모가 아니라 소유 리스트 기반으로**: 캐릭터가 클론으로 승격되며 다른 부모로 reparent돼도, 로더가 생성 시 담아둔 `List`만 순회해 Destroy하면 전부 커버된다. 부모 순회는 reparent된 것을 놓친다.

### 평가 시 통했던 검증 기법

- **git diff로 "보호 블록 불변"을 라인 단위 증명**: 코어 루프를 감싸는 리팩터는 "본문을 안 건드렸다"가 생명이다. diff에 **가드 라인 추가·메서드 이름 변경·필드 선언 변경만** 있고 보호 대상(충돌 해소/밀기/중앙 틱/IgnoreCollision/오버랩 복구) 본문 라인이 0인지 직접 확인한다.

- **레벨 전환 잔존은 "다음 프레임"에 센다**: `Destroy`는 프레임 끝에 지연 실행되므로, 로드 직후 세면 옛것+새것이 함께 잡힌다(4/2). 다음 execute_code 호출(프레임 경과 후)에 다시 세어 2/1을 확인해야 진짜 클린 판정이다.
- **게이트를 절대 좌표로 양방향 실측**: "지면에선 못 닿고 발판 위에선 닿는다"는 발바닥 `bounds.min.y` 최댓값을 **월드 좌표**로 재고 목표 높이와 직접 비교한다(지면 0.706 vs 클론 위 1.726 vs 렛지 1.20). 실패해야 할 캐릭터(무거운형)는 **발판 위에서도** 목표에 못 미침(0.134<1.20)을 보여 "영구 불가 → 역할 강제"를 증명한다.

## #5 — Phase 3-3 설치형 틱 기믹 시스템 (2026-07-22) · `시스템조립` · 88점

> #3의 런타임 주입 축을 **"드롭인 설치형 상호작용 오브젝트"로 확장**. 레벨 정의를 안 건드리고 프리팹을 놓기만 하면 중앙 틱 세계에 편입되는 구조.

### 핵심 접근

- **설치형 계약은 인터페이스 2개로 쪼갠다 — 수신(IActivatable)과 구동(ITickGimmick)**: "스위치→대상 다대상 배선"은 `SetActivated(bool)`+`IsActivated` 수신 계약으로, "결정성 세계 편입"은 `ResetGimmick()`+`DriveGimmickTick(tick)` 구동 계약으로 분리한다. 로더가 `GetComponentsInChildren<ITickGimmick>(true)`로 자동 수집해 매니저에 주입하면 레벨 데이터 정의 무수정 드롭인이 성립한다. Unity는 인터페이스 제네릭 GetComponentsInChildren을 공식 지원한다. 배선 필드는 `MonoBehaviour[]` 직렬화 + Awake 캐스트 검증(실패 시 LogError — 무음 skip 금지)으로 우회한다.

- **리셋 경로는 반드시 전수 조사한다 — 정상 경로(EnterSelecting)만 리셋하면 우회 경로(RestartTake)에서 잠복한다**: 상태 진입점이 여러 개면(선택/확정/되감기/테이크 재시작/사망) 각 경로가 리셋을 타는지 코드로 추적하라. 이번엔 Critic이 "RestartTake는 EnterSelecting을 우회한다"를 사전 적발해 1회차 실측 통과로 이어졌다.
- **순회 루프 안에서 상태 전환 메서드를 즉시 호출하지 않는다 — 플래그 지연 + 루프 밖 단일 지점 처리**: 킬존이 DriveGimmicks 순회 도중 RestartTake를 즉시 호출하면 리셋 이후 배열 뒤쪽 기믹만 한 번 더 구동되어 콜백 위치에 따라 1틱 위상 desync가 난다(실측). 콜백은 `_isDeathPending=true`만 세우고, 처리부는 순회 완료 후·재생/기록/틱 증가 전에 두고 `return`한다. 검증은 `_tick`과 기믹 위상 카운터의 일치로 잰다.
- **중첩 프리팹 인스턴스는 MCP `create_child + source_prefab_path`로 설치한다 — 수작업 YAML 불필요**: bake 복사는 "프리팹 수정 → 레벨 전파"라는 재사용 계약을 무너뜨린다. 인스턴스 간 참조 배선(_targets)은 prefab stage를 열어 설정하고, 완료 후 `.prefab`에서 `PrefabInstance`/`m_SourcePrefab` grep으로 증명한다.

### 반복 성공 — Phase 3-3b 깨지는 발판 + 정체성 포탈 + 캐리 수정 (2026-07-23, 99점)

> 설치형 계약이 **매니저 코드 0줄 수정**으로 신규 기믹 2종을 흡수함을 실증. 확장 시 배운 추가 기법:

- **"지지체 소유" 판정은 배제 조건을 좁게**: 캐리 대상에서 빼는 근거는 "다른 콜라이더가 근처에 있다"가 아니라 **"x범위가 캐릭터 수평 중심을 포함하는 다른 지지체가 발밑에 있다"**로 한정한다. 넓게 잡으면 밀착한 이웃(클론)이 정당한 탑승자를 오배제한다. 중첩 물리 질의는 반드시 별도 재사용 버퍼로(같은 버퍼면 바깥 루프 오염).
- **쌍(pair) 장치의 상태 세팅은 행위자 쪽이 건다**: 포탈 도착 래치를 도착측 자체 감지에 맡기면 구동 배열 순서에 따라 같은 틱에 즉시 반사(핑퐁)된다. 텔레포트를 실행한 출발측이 도착측 래치를 직접 세팅하면 순서 무관.
- **트리거 장치의 레이어는 접지 질의와 교차 검증**: 트리거 콜라이더를 접지 마스크에 포함된 레이어(Ground류)에 두면, 트리거도 잡는 질의 오버로드가 그것을 지면으로 오인해 무한 점프가 난다. 상호작용 전용 트리거는 Default에 둔다.
- **disabled 콜라이더의 bounds는 무효(0 크기)** — 꺼진 콜라이더 기준으로 점유 질의를 계속하면 조용히 아무것도 안 잡힌다. 꺼진 상태에선 질의를 스킵하거나 bounds를 캐시해 둔다.
- **"영구 게이트"는 도달고 산술로 증명**: h = (jumpForce/mass)²/(2·9.81·gravityScale)로 각 정체성의 최대 도달고를 계산해 "이 정체성은 점프로 못 오르고 이 장치로만 오른다"를 배치 전에 수치로 확정한다(#1 검증 기법의 응용).
